# Pokémon GO 定位工具與安全自動化研究

> **建立日期：** 2026-09-01  
> **目的：** 釐清 iAnyGo 與同類定位工具的公開功能宣稱、公開可驗證的風險資訊，以及如何把「路線規劃／自動化」的技術研究放在不碰 Pokémon GO 帳號與服務規則的測試環境。  
> **結論先講：** iAnyGo、AnyTo、Dr.Fone Virtual Location 都公開販售「變更 GPS、模擬路線」功能，部分更宣稱可自動抓寶；但 Pokémon GO 的現行公平遊戲政策把 GPS spoofing、未授權第三方軟體與 add-on 明列為作弊，帳號可能受警告、停權或永久終止。故本研究**不建議、也不提供**用測試帳號實作自動走路／自動抓寶的流程。若目標是研究 bot 路線規劃與自動化，應改在自建模擬器或不連線遊戲服務的 sandbox 驗證；若目標是合規減少手動操作，官方 Pokémon GO Plus + 是可考慮的裝置方向。

---

## 1. 問題拆解

原始需求其實混合了三件不同的事：

1. **GPS 虛擬定位**：將手機回報的位置改為另一處。
2. **路線規劃／移動模擬**：在地圖上規劃點到點或多點路徑，讓座標沿路徑變動。
3. **遊戲操作自動化**：掃描目標、轉補給站、丟球、抓寶等。

前兩項是一般定位工具的產品功能；第三項一旦對 Pokémon GO 正式客戶端及帳號執行，就不只是「技術測試」，而是會直接落在官方定義的作弊範圍。

## 2. 官方規範：風險不是推測

Scopely Explore（原 Niantic）目前條款明文禁止：

- 使用未授權方式存取服務，包括修改版或非官方第三方軟體；
- 偽造或改變裝置位置，例如 GPS spoofing；
- 以同一服務使用多帳號、共用帳號等行為。

《Pokémon GO Gameplay Fairness Policy》也把「GPS location spoofing」與透過第三方軟體／add-on 未授權存取遊戲客戶端或後端列為作弊。官方處分可能是：

- 第 1 擊：約 7 天警告，且稀有 Pokémon、交換、送禮、Routes 等遊戲功能可能被限制；
- 第 2 擊：約 30 天暫時停權；
- 第 3 擊：永久終止帳號；
- 官方同時保留不經三擊、直接終止帳號的權利。

這也表示「拿一個小帳試玩」不能消除風險：它可能被處分，而且以多帳號迴避玩法本身亦在條款禁止範圍內。帳號、付款、裝置與其他資料之間是否會被關聯，官方未公開具體偵測邏輯；不應把廠商的「不會被偵測」行銷當成保證。

## 3. 市面工具：功能地圖，不是安全或成功背書

下表僅整理各廠商**自己的公開宣稱**；沒有獨立驗證其穩定性、相容性或「安全率」。產品頁常隨 iOS / Android / 遊戲版本改動，購買前仍須看當下條款與退款條件。

| 工具 | 廠商公開宣稱 | 與本需求的關係 | 重要界線 |
| --- | --- | --- | --- |
| Tenorshare iAnyGo | iOS/Android 改定位、單點／多點路徑、搖桿；頁面另宣稱 Pokémon GO 自動抓寶、掃描補給站與路線生成 | 最直接對應「虛擬移動＋自動抓寶」 | 對 Pokémon GO 使用即與官方禁止 GPS spoofing／第三方 add-on 的規範衝突 |
| iMyFone AnyTo | 瞬移、雙點／多點路徑、搖桿、GPX；頁面另宣稱 auto catcher、IV scanner 等遊戲功能 | 同樣涵蓋定位與遊戲輔助 | 同上；「0% ban」之類字樣是廠商行銷，非官方保證 |
| Dr.Fone Virtual Location | iOS/Android 改定位、單／多站路線、搖桿、GPX、速度模擬與冷卻計時器 | 可用來理解一般路線模擬產品的功能形態 | 其 Pokémon GO 導向頁面不會改變遊戲方的規範 |

### 產品文案與可採信程度

這類產品頁面普遍使用「safe」、「anti-detection」、「0% ban」或「without risk」等語言，也會教人用「自然移動」與冷卻計時器。這是明顯的銷售主張，不是可驗證的安全承諾；反過來，遊戲方官方條款清楚說明其會以合法機制偵測與回應作弊，並可能不退款。因此本報告不把任何一項列為「安全」或推薦試用。

## 4. 公開回報與心得：可得資訊的限制

本次能直接驗證的公開材料，主要是官方政策與各家產品頁；Reddit / Trustpilot 等第三方評論頁在研究環境中受到存取限制，無法逐則核對原始貼文及帳號背景。因此：

- **不以匿名論壇個案推導封號率、成功率或安全排名。** 同一人可能重複發文，且負評、版本、OS、帳號歷史與其他工具使用狀況常無法驗證。
- 可確認的是，廠商本身確實把「可改 GPS、可規劃路線、可自動抓寶」當成賣點；這不等於獲遊戲方允許。
- 可確認的是，遊戲方公開列出 GPS spoofing、未授權第三方軟體／add-on 為作弊，並公開描述警告、停權與永久終止的處分梯度。

所以面對任何「用了很久沒事」或「某版本安全」的心得，最好的解讀是：它只描述該名使用者某段時間的經驗，**不能**推論未來不會被偵測或不會被處分。

## 5. 若真正目標是研究 bot：建議的合規測試範圍

不對 Pokémon GO 客戶端、帳號或後端做自動化，仍然可以完整驗證大部分工程問題：路線規劃、地圖資料、狀態機、視覺辨識、點擊可靠度、節流、錯誤復原與測試報表。

### A. 自建「抓寶地圖」sandbox（最接近需求）

建立一個本機或私有網頁／小型 app：

- 輸入為合成的 PokéStop、目標物、背包數量、距離與時間；
- 路徑規劃器輸出點序與預估步行距離；
- bot 只對**我們自己的 UI**進行辨識與點擊；
- 使用固定 seed 的模擬器重播場景，量測成功率、耗時、漏點與失敗復原；
- 保存 route JSON、截圖、event log，讓每次回歸測試可比較。

這能驗證「自動規劃路線＋自動抓寶」的技術架構，卻不會偽造真實位置或干擾第三方服務。

### B. 路線規劃器獨立測試

只針對公開地圖或自建測資實作並比較：最近鄰、時間窗、背包容量、休息／補給點、最短路徑等策略。輸出 GPX 或 JSON 僅用於可視化與 sandbox replay，**不送往 Pokémon GO**。

### C. 合規的實際遊戲自動化選項

若需求是「人在正常移動時，減少持續盯螢幕與手動按鍵」，官方 Pokémon GO Plus + 的公開說明包含自動丟球、抓 Pokémon，以及自動轉 PokéStop；它需要與裝有官方 app 的手機配對，並非獨立 bot。這是與偽造位置完全不同的路徑。

## 6. 建議的下一步（不啟用遊戲 bot）

1. 先寫一份 sandbox 規格：地圖大小、假資料格式、成功定義、允許的錯誤率與 log 欄位。
2. 用一個私有網頁做最小版本：隨機生成點位 → 規劃路線 → bot 在自有 UI 完成「發現／移動／收集」回合。
3. 測試重點放在可重播性與失敗復原，而不是規避偵測；產出測試報告後，再決定是否值得擴充。
4. 若要在真實 Pokémon GO 中減少手動操作，僅評估官方 Pokémon GO Plus + 與官方 app 的配對體驗，不混入定位工具或 UI bot。

## 本研究的界限

本文不包含安裝教學、帳號操作、自動抓寶設定、路線座標、繞過偵測、冷卻時間規避或任何對 Pokémon GO 的自動化執行指令。這些內容會直接協助違反服務規則；而對 bot 技術本身的研究，可在上述 sandbox 範圍內完成。
